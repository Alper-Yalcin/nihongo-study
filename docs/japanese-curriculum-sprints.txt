# Japanese Learning Platform — Micro-Sprint Execution Plan

Source plan: japanese-curriculum-plan.txt
Revision focus: split heavy sprints into 1–2 day micro-sprints, separate logic from UI, reduce hidden complexity, preserve ALL features and phase order, keep MVP fast.

---

## Part 1 — Heavy Sprints Identified

Each of these bundled too much. Splitting below.

| # | Original Sprint | Why it's heavy | Risk |
|---|----------------|----------------|------|
| S1 | Level 1 Data Seeded | 8 missions × (vocab + grammar + branching + dialogue + 3-tier feedback) = hours of authoring + shape drift | Data typos go undetected until late; mid-sprint interface changes force rework |
| S2 | Debug / Dev Tooling | 7+ distinct tools (inspector + mutators) in one UI | Scope creep; "just one more button" |
| S3 | Mission Flow Shell | 5 sequential phases (scenario/vocab/grammar/examples/tasks/complete) wired at once | Phase transition bugs compound |
| S4 | Task Engine v1 | 4 task types with subtle answer-matching rules | Answer normalization edge cases bleed across types |
| S5 | Task Engine v2 | Token logic (sentence-build) + TTS integration (listening) in one sprint | Two fundamentally different risk profiles bundled |
| S6 | Dialogue Chain | Turn state machine + UI + avatars + feedback pick | Logic and UI coupled, hard to test independently |
| S7 | Branching Choice | 3-outcome router + UI panel + downstream chain routing | Same logic/UI coupling |
| S8 | Persistence & Checkpoint Gating | Storage schema + mission unlocks + checkpoint scoring + fail screen + badge | 4 distinct systems share one sprint |
| S9 | Level 2 Data | 10 missions of authoring | Long, boring, typo-prone |
| S10 | Level 3 Data | 10 missions of authoring + new character | Same as above plus net-new character data |
| S11 | Vocab Progress + SRS Core | Schema + interval math + selection algo + warm-up UI + validation helper | 5 systems; hidden scheduling complexity |
| S12 | Adaptive State Engine | Schema + update rules + 2 visible behaviors + debug | Silent engine + visible effect bundled; hard to debug |
| S14 | Fail-Forward System | Flag persistence + recovery detection + UI callback line | Cross-cuts UserState, TaskRunner, emotional feedback |
| S15 | Character Evolution | Per-character data variants + renderer + emotional variants | Data shape change + rendering logic bundled |
| S16 | Layout & Typography Pass | Design tokens + mission redesign + shell redesign + motion | Entire visual system in one sprint |
| S18 | Confidence-Aware UI | 3 modes × multiple rules each | Three UI variants built simultaneously = 3× regression surface |
| S19 | Relationship & Re-Entry UI | 4 distinct features (bubble variants + avatars + re-entry splash + streak) | Unrelated features bundled |
| S21 | Challenge Missions | Data authoring + strict scoring rules + reward logic | Data + engine + reward coupled |
| S23 | N5 JL4–JL7 | 4 full levels of authoring | Multi-week sprint masquerading as one |
| S24 | N5 JL8–JL14 + Full N5 Review | 7 levels + 50-question review session | Even larger |

### PHASE 1 — CORE MISSION LOOP (UI Phase A — functional only)

**S3a · Mission Shell — Scenario + Complete**
- Goal: Mission can be entered and exited.
- Scope: `MissionRunner` with only 2 phases: `scenario` (shows scenario + goal + Begin) and `complete` (shows successMessage + back). "Skip to complete" button in dev.
- Checkpoint: Open L1-U1-M1 → see scenario → skip → complete screen with success line.

**S3b · Mission Shell — Content Phases**
- Goal: Static content displays between scenario and complete.
- Scope: Add phases vocab (plain table), grammar (quote block), examples (numbered list). Next/Back navigation. Phase `tasks` still stubbed.
- Checkpoint: Step through all 5 phases of L1-U1-M1; each shows the right static content.

**S4a · Task Engine — MC + Fill-in-Blank**
- Goal: Two simplest task types grade.
- Scope: `TaskRunner` iterator; `multiple-choice` (radio) and `fill-in-blank` (text input) components. Trim+case-normalize match. Wrong → show `explanation` → retry. Retry counter per question.
- Checkpoint: A mission with only these types grades all questions correctly; retries counted.

**S4b · Task Engine — Translation en→jp & jp→en**
- Goal: Free-text translation tasks grade.
- Scope: Two new task components sharing one answer-normalizer that supports `A / B` alternatives in `correctAnswer`.
- Checkpoint: L2-U1-M1 (mix of all 4) grades fully; alternatives accepted (e.g. `さん / san`).

**S5a · Task Engine — Sentence-Build**
- Goal: Token-based answer construction.
- Scope: `sentence-build` component. Token bank = shuffled correctAnswer split. Tap-add, tap-remove. Submit validates exact order. No animations.
- Checkpoint: Build わたしはケンジです from tokens; wrong order rejected; correct accepted.

**S5b · Task Engine — Context-Select**
- Goal: Scenario-emphasized choice variant.
- Scope: `context-select` component reuses MC logic but shows `prompt` as a larger scenario card. No new logic.
- Checkpoint: L1-U1-M1 branching-style context questions render scenario prominently; grading inherited from MC works.

**S5c · Task Engine — Listening-Recognition**
- Goal: TTS-backed audio question.
- Scope: `listening-recognition` plays target via `speechSynthesis` (ja-JP voice). Fallback warning if voice missing. Play button re-triggers audio.
- Checkpoint: Audio audibly speaks the Japanese target in Chrome; replay works; options grade like MC.

**S6a · Dialogue Chain — Turn State Machine (Logic Only)**
- Goal: Turns advance correctly in state, no visual polish.
- Scope: `useDialogueChain(chain)` hook emits current turn, expected answer, advance/reset functions. Console-log UI only.
- Checkpoint: Run L1-U2-M5 chain through console — correct answer advances, wrong answer stores missed item + advances (dialogues always forward).

**S6b · Dialogue Chain — UI Binding**
- Goal: Chain has a real UI.
- Scope: `DialogueChainPlayer` component using S6a hook. Speaker avatar stub (colored circle + initial), bubble layout, learner turn reuses sentence-build/fill-in from Task Engine. On last turn → emotional feedback line + successMessage.
- Checkpoint: L1-U2-M5 dialogue plays visually across 3 turns with correct avatar + advance behavior.

**S7a · Branching Choice — Outcome Router (Logic)**
- Goal: Pick-to-outcome logic lives in a hook.
- Scope: `useBranchingChoice(bc)` returns `onPick(optionId) → {result, outcomeText, next}`. Result enum: `wrong | partial | correct`. No UI yet.
- Checkpoint: Unit-style test via debug panel: calling onPick with each option on L1-U1-M1 returns expected result and outcome text.

**S7b · Branching Choice — 3-Option Panel (UI)**
- Goal: Visual branching panel.
- Scope: `BranchingChoicePanel` uses S7a hook. 3 options, pick → outcome card shown → Retry (wrong) / Continue (partial/correct). Runs AFTER examples, BEFORE tasks/dialogue.
- Checkpoint: All 3 outcomes of L1-U1-M1 reachable; correct option unlocks dialogue chain.

**S8a · Persistence — Schema + Helpers**
- Goal: Typed read/write around localStorage.
- Scope: `jlearnStorage.ts` exports `readProgress()`, `writeProgress(p)`, `readVocab()`, `writeVocab(v)`, `readUserState()`, `writeUserState(u)`. Schema defined, no callers yet.
- Checkpoint: Call from debug panel — round-trip write/read of a fixture returns identical object.

**S8b · Persistence — Completion + Unlock Gating**
- Goal: Missions mark complete and gate future unlocks.
- Scope: Hook MissionRunner completion → `writeProgress`. World-map reads progress → locks missions/units/levels per plan (linear within unit; unit gated by prior unit's checkpoint).
- Checkpoint: Finish L1-U1-M1 → M2 unlocked, M3 still locked. Refresh → state intact.

**S8c · Persistence — Checkpoint Scoring + Fail Screen + Badge**
- Goal: Checkpoint missions gate level progression.
- Scope: Checkpoint missions score pass/fail at 80%. Fail → list missed items + retry CTA. Pass → write badge, unlock next level.
- Checkpoint: Fail L1-U3-M8 (5/12) → fail screen; pass retry (11/12) → Social Starter badge in storage, L2 unlocks.

#### 🏁 MILESTONE — MVP-PLAYABLE
Level 1 fully clickable end-to-end: scenario → vocab/grammar/examples → branching → tasks → dialogue → completion → persisted → next mission → checkpoint → badge → L2 unlocked (empty). Debug tools in place.

### PHASE 3 — MEMORY & ADAPTIVE ENGINES

**S11a · SRS — Tracking (Silent)**
- Goal: Per-vocab progress schema + updates, no selection yet.
- Scope: `VocabProgress` schema. TaskRunner hook: on question submit with `targetVocabId`, update `masteryLevel`, `errorCount`, `lastSeenAt`, `seenInMissions[]`. No nextReviewAt math yet.
- Checkpoint: Play mission, miss 3 items — debug panel shows those 3 with errorCount ≥ 1.

**S11b · SRS — Scheduling**
- Goal: Intervals computed.
- Scope: Add `nextReviewAt` computation using plan's intervals (0→now, 1→+1d, 2→+3d, 3→+7d, 4→+30d). Pure function tested via debug panel.
- Checkpoint: Debug panel shows `nextReviewAt` correctly set after each mission; unit-assert function `validateVocabProgress` clean.

**S11c · SRS — Selection (Warm-Up)**
- Goal: Due items surface at level entry.
- Scope: When entering a level, if any vocab has `nextReviewAt <= now`, warm-up mission shows 3–5 questions drawn from due items. UI: label "Warm-up".
- Checkpoint: Use debug to set yesterday's lastSeenAt + mastery=1 on 3 items → reopen level → warm-up with those 3.

**S12a · Adaptive State — Tracking (Silent)**
- Goal: UserState maintained, no visible effects.
- Scope: `UserState` schema. Update rules: perfect first-try → confidence up; 3 retries → down; mission with Yuki → relationshipLevels.yuki tick (every 3 missions = +1 stage); casual branch picks → formalityPreference drifts casual; `missedDays` from last session timestamp.
- Checkpoint: Play 3 perfect missions → debug shows confidence=high; miss badly → drops to low.

**S12b · Adaptive State — Visible Behavior**
- Goal: First real effect — warm-up length adapts.
- Scope: low→5 warm-up Q, medium→3, high→0. Mission completion screen shows (debug only for now) which state tier it used.
- Checkpoint: Force each state via debug → warm-up length matches; turn debug off → state still drives behavior silently.

**S13 · Layered Emotional Feedback**
- Goal: Completion feedback tier reflects performance.
- Scope: Pick tier from final score object: perfect (no retries, no hints) / good (1–2 retries) / struggle (3+). Render appropriate copy above successMessage. Data already has tiers from S1a–c, S9, S10.
- Checkpoint: Replay L1-U1-M1 three times — clean, 1 retry, 3 retries — each shows correct tier.

**S14a · Fail-Forward — Flag Storage**
- Goal: Partial branching picks record a recovery flag.
- Scope: When branching returns `partial`, write `{targetId, missionsRemaining: 2, createdAt}` to UserState recovery list. No UI yet.
- Checkpoint: Pick partial in L1-U1-M1 → debug panel shows new recovery flag referencing おじゃまします.

**S14b · Fail-Forward — Recovery Injection + Callback**
- Goal: Second-chance question appears, callback copy fires.
- Scope: TaskRunner queries active recovery flags per mission entry; if any flag's `targetId` matches a vocab/grammar in upcoming mission, insert an extra question at the end. Correct answer → clear flag + append callback line to that mission's emotional feedback.
- Checkpoint: Trigger partial in M1 → play M2 → injected question on おじゃまします → answer right → Mrs. Tanaka callback line shown on completion; flag gone.

**S15a · Character Evolution — Stage Tracking + Data Shape**
- Goal: Per-character stage variant data shape exists.
- Scope: Dialogue turn structure upgraded: `line` may be `string | Record<stage, string>`. Author stage-2 variants for Yuki + Mrs. Tanaka lines in L1–L3.
- Checkpoint: `npx tsc --noEmit` clean; data spot-check shows variants present.

**S15b · Character Evolution — Renderer Picks Variant**
- Goal: Dialogue renderer uses current stage.
- Scope: `DialogueChainPlayer` reads `relationshipLevels[characterId]` and picks the matching variant (fallback to default if stage variant absent). Emotional feedback may also pick stage variant where authored.
- Checkpoint: Force `relationshipLevels.yuki = 2` → L2 dialogue with Yuki uses casual variant (どこから来たの).

#### 🏁 MILESTONE — SYSTEMS-STABLE
All engines green. Reset → replay L1+L2+L3 → no runtime errors; validators clean. **No major UI redesign starts before this point.**
